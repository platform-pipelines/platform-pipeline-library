# Images & supply chain

Images go to GHCR and build artifacts go to GitHub releases
(`publish.githubRelease`), so there is no artifact store to run.

## Image builders

[`buildImage`](../reference/images/buildImage.md) routes on `imageBuilder`,
because the way you build without a root daemon depends on where your agents run.

| `imageBuilder` | Needs | Trade-off |
|---|---|---|
| `kaniko-docker` (default) | pinned plugin set | needs a docker socket on the agent |
| `kaniko-k8s` | `kubernetes` plugin + pod template | no socket anywhere; the only truly unprivileged option |
| `buildah` | toolbox agent, subuid + fuse-overlayfs | no daemon, but host setup required |

```yaml
imageRepo: ghcr.io/acme/orders-api
dockerfile: Dockerfile
imageBuilder: kaniko-docker     # kaniko-docker | kaniko-k8s | buildah
quality:
  sbom: true
  signImage: true
```

## Supply chain

- **SBOM** ([generateSbom](../reference/images/generateSbom.md)): CycloneDX,
  generated by Trivy, archived and fingerprinted. With it you can answer "are
  we affected by this CVE" across every deployed service in minutes, rather
  than rebuilding each one.
- **Signing** ([signImage](../reference/images/signImage.md)): cosign keyless.
  It signs the digest, not the tag, and attaches the SBOM as an attestation.
  Signing only matters if an admission policy (Kyverno, Sigstore
  policy-controller) rejects unsigned images.
- **Audit trail** ([logAudit](../reference/utilities/logAudit.md)):
  `.ci-audit.jsonl`, archived every run.
